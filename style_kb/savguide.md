# SAV-3001 Documentation Style Guide

## Purpose
To provide clear and effective documentation that helps users successfully complete tasks and troubleshoot issues.

## Audience
Users of the SAV-3001 system, including those working with templates and connectors.

## Tone
Professional and supportive, aiming to guide users through tasks and troubleshooting.

## Voice
Consistent and authoritative, providing clear instructions and solutions.

## Writing Principles
- Ensure clarity and precision in instructions.
- Anticipate user errors and provide guidance to prevent them.
- Validate steps against potential user errors.

## Headings

### Heading Rules
- Use descriptive headings that clearly indicate the content of the section.

### Capitalization Rules
- Capitalize the first letter of each major word in headings.

## Terminology

### Preferred Terms
- Authenticate & Confirm
- SAP HANA Database Connector
- Google Analytics 4 Connector

### Avoided Terms
- None specified.

### Terminology Examples
- Use "Authentication Failed" for error indications.

## Grammar

### Active / Passive Voice
- Use active voice to make instructions direct and clear.

### Pronouns
- Use second-person pronouns to directly address the user.

### Sentence Length
- Keep sentences concise to enhance readability.

## Lists

### Bulleted Lists
- Use for listing troubleshooting steps or common pitfalls.

### Numbered Lists
- Use for sequential steps in procedures.

## Procedures

### Task Writing
- Include detailed examples and common pitfalls.
- Validate steps against potential user errors.

### Step Writing
- Provide clear, sequential instructions for task completion.

## User Interface Language

### Buttons
- Use exact button labels as they appear in the interface.

### Menus
- Refer to menu items as they are labeled in the interface.

### Dialogs
- Clearly describe dialog options and expected user actions.

### Messages
- Provide guidance on interpreting and resolving error messages.

## Accessibility

### Inclusive Language
- Use language that is inclusive and respectful to all users.

### Bias-Free Language
- Avoid language that could be perceived as biased or discriminatory.

### Alt Text
- Ensure all images have descriptive alt text for accessibility.

## Formatting

### Notes
- Use notes to provide additional context or tips.

### Warnings
- Highlight warnings to prevent user errors.

### Code Examples
- Provide code examples where applicable to illustrate solutions.

### Links
- Ensure links are descriptive and lead to relevant content.

## Examples
- Include examples to illustrate common pitfalls and solutions.

## Exceptions
- Document any exceptions to standard procedures or terminology.
